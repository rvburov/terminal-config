# Terminal Config

Своё оформление Bash: часы, цветная строка, Git-статус и собственное дерево файлов с иконками. Без oh-my-bash, eza и менеджеров тем. Подходит для Git Bash в Windows, Bash в Linux и macOS, включая SSH-серверы. Работает в WezTerm, Alacritty и других терминалах.

Пример строки в широком окне:

```text
16:40:12 | user@server | terminal-config | main +2 ~1 ?3 ↑1
> 
```

Время — серое, пользователь и имя компьютера или сервера — зелёные, каталог — голубой, ветка — фиолетовая. Чистый Git-статус зелёный, изменения жёлтые, конфликты красные. После неудачной команды знак `>` становится красным.

## Установка

Нужны Bash 3.2 или новее и Git. В Windows сначала установите Git for Windows и откройте **Git Bash**. В macOS запустите `bash`, если обычно используете zsh.

Из каталога проекта выполните:

```bash
bash install.sh
```

Затем откройте новую вкладку терминала. Для проверки выполните `ls`: появится дерево первого уровня с иконками. Сначала идут папки по алфавиту, затем файлы по расширению и имени. Файлы без расширения идут перед группами расширений.

Установщик ничего не скачивает и не устанавливает системные пакеты. Для иконок выберите **Nerd Font** в настройках терминала, например JetBrainsMono Nerd Font. При SSH шрифт нужен на вашем компьютере; на сервере достаточно Bash и Git.

## Перенос через GitHub

На другом компьютере или сервере выполните команды в Bash.

```bash
git clone https://github.com/rvburov/terminal-config.git
cd terminal-config
bash install.sh
```

Установка применяется к текущему пользователю в той системе, где выполнена команда. Настройки Bash копируются отдельно, поэтому перенос или удаление скачанного проекта не сломает установленную строку.

Для обновления:

```bash
git pull --ff-only
bash install.sh
```

## Git-статус

Показывается внутри репозитория и обновляется после команд.

| Обозначение | Значение |
| --- | --- |
| `main` | Текущая ветка; при detached HEAD — короткий хеш коммита |
| `✓` | Рабочее дерево чистое |
| `+2` | Два пути с изменениями в индексе, подготовленными к коммиту |
| `~1` | Один путь с изменениями вне индекса |
| `?3` | Три неотслеживаемых файла или каталога |
| `!1` | Один конфликт |
| `↑2` | Два локальных коммита впереди upstream |
| `↓1` | Один коммит позади upstream |

Числа относятся к путям, а не к строкам кода. Один файл может иметь и `+`, и `~`. Содержимое нового неотслеживаемого каталога считается одним путём. Сравнение с upstream использует локальные сведения Git: `git fetch` обновляет их. Оформление само не обращается к сети.

В узком окне длинные имена сокращаются с начала. Имя компьютера показывается от 32 колонок, имя пользователя добавляется от 100 колонок, Git — от 60. Если подробные счётчики не помещаются, остаётся `*` для изменений, `!` для конфликта или `↕` для расхождения. Время сокращается до `HH:MM`, а при ширине до восьми колонок остаётся только `>`.

В Git Bash под Alacritty и WezTerm на Windows статус выводится отдельной строкой. На следующей строке Bash показывает `>` и принимает команду. Так часы, путь и ветка переносятся вместе с историей, а Readline перерисовывает только ввод. Часы и Git обновляются перед новой командой. В других терминалах по умолчанию используется одна строка. Для выбора вида можно указать `export TERMINAL_CONFIG_LAYOUT=stacked` или `export TERMINAL_CONFIG_LAYOUT=inline` в `~/.bashrc` перед подключением проекта. Двухстрочный вид требует Bash 4.4 или новее.

### Перенос текста в Alacritty и WezTerm для Windows

В Alacritty 0.17.0 на Windows 10 с Git Bash помогли двухстрочное приглашение и обновление Microsoft ConPTY. Чтобы повторить эту настройку, закройте Alacritty и выполните команду из отдельного PowerShell в каталоге проекта. Подставьте путь к установленному Alacritty.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\windows\install-conpty.ps1 -AppDir "C:\Programs\Alacritty"
```

Скрипт для x64 проверяет контрольные суммы и подписи Microsoft и устанавливает `conpty.dll` и `OpenConsole.exe` рядом с указанным приложением. При замене файлов скрипт сообщает путь к резервной копии. Обновление терминала через менеджер пакетов может заменить этот каталог. [Пакет Microsoft.Windows.Console.ConPTY](https://www.nuget.org/packages/Microsoft.Windows.Console.ConPTY/1.25.261109001) · [Обсуждение в Alacritty](https://github.com/alacritty/alacritty/issues/8576)

В локальном Git Bash внутри WezTerm 20240203 с этой же ConPTY удалось воспроизвести сбой. После двух `ls` в домашнем каталоге и 24 сужений и расширений окна курсор переместился с нижней строки наверх, и в дереве появились лишние `>`. В штатном окне Git Bash (mintty) перенос на этом компьютере работал. Для работы с сервером можно выбрать его SSH-профиль в меню WezTerm. Такое подключение использует терминал сервера. [Разбор перерисовки в WezTerm](https://github.com/wezterm/wezterm/issues/1265)

Если это произошло в WezTerm на пустой строке Bash, нажмите **Ctrl+L** и выполните `ls` снова. Если команда уже набрана и курсор прыгает, отмените её через **Ctrl+C**, очистите экран и введите заново. В проверке после resize Bash принимал символы, которые WezTerm не показывал. Очистка восстанавливает видимую область, а искажённые строки выше могут сохраниться.

## Сочетания клавиш в Windows

В каталоге `windows` сохранены настройки для Alacritty 0.17 и WezTerm 20240203 или новее. Буквенные сочетания привязаны к физическим клавишам. На русской раскладке клавиша английской `V` соответствует `М`, а `C` соответствует `С`.

| Действие | Сочетание |
| --- | --- |
| Копировать выделенное | `Ctrl+Shift+C` или `Ctrl+Insert` |
| Вставить из буфера | `Ctrl+V`, `Ctrl+Shift+V` или `Shift+Insert` |
| Прервать команду | `Ctrl+C` |
| Поиск вперёд в Alacritty | `Ctrl+Shift+F` |
| Поиск назад в Alacritty | `Ctrl+Shift+B` |
| Новая вкладка WezTerm | `Ctrl+Shift+T` |
| Закрыть вкладку WezTerm | `Ctrl+Shift+W` |
| Следующая / предыдущая вкладка WezTerm | `Ctrl+Tab` / `Ctrl+Shift+Tab` |
| Выбор профиля WezTerm | `Ctrl+Shift+L` |
| Командная палитра WezTerm | `Ctrl+Shift+P` |
| Переименовать вкладку WezTerm | `Ctrl+Shift+R` |

Установка Bash через `install.sh` и подключение сочетаний выполняются отдельно. Настройки клавиш применяются на компьютере, где запущен терминал. При подключении по SSH скопированные файлы на сервере используются для оформления Bash.

### Alacritty

Сохраните резервную копию своего `%APPDATA%\alacritty\alacritty.toml`. Замените раздел `[keyboard]` в этом файле содержимым `windows/alacritty-keybindings.toml`. Если раздела ещё нет, добавьте его в конец. Числовые коды клавиш в этом файле рассчитаны на Windows. После сохранения откройте новое окно Alacritty.

### WezTerm

В своём `~/.wezterm.lua` добавьте следующую строку после настроек `config` и перед `return config`. Укажите фактический путь к скачанному проекту.

```lua
dofile('C:/rvburov/terminal-config/windows/wezterm-keybindings.lua')(config)
```

Модуль задаёт сочетания и таблицы команд поиска и копирования. При наличии своих сочетаний сравните их с модулем перед подключением. Скачанный каталог должен оставаться доступным по указанному пути. Для автономной копии можно перенести Lua-файл в домашний каталог и поменять путь в `dofile`.

Профили успешно загружены установленными Alacritty и WezTerm. Проверены назначения физических клавиш для EN и RU и отсутствие двойного действия вставки в обычном режиме. Полная автоматическая проверка копирования и вставки через системный буфер осталась неподтверждённой.

## Цвета и файлы

| Тип | Цвет |
| --- | --- |
| Каталоги | Голубой |
| Обычные файлы | Светло-серый |
| Ссылки | Бирюзовый |
| Исполняемые файлы и shell-скрипты | Зелёный |
| Markdown | Светло-жёлтый |
| JSON, YAML, TOML, INI | Светло-зелёный |
| Архивы | Оранжевый |
| Изображения | Розовый |
| PDF и Word | Фиолетовый |

Дерево, иконки и палитра написаны в `shell/files.sh` на Bash. Сторонняя программа для вывода дерева не нужна.

```bash
ls                   # один уровень, папки сверху
ls -a                # со скрытыми файлами
ls --level=2         # два уровня
tree                 # дерево глубиной до трёх уровней
tree --level=5 /path  # другая глубина и каталог
```

Глубина задаётся от 0 до 64; значение 0 показывает только корень. Расширения группируются без учёта регистра ASCII: `.TXT` и `.txt` относятся к одному типу. Символические ссылки отображаются отдельно, обход по ним не выполняется. Опции подробного системного списка, например `ls -la`, передаются обычному системному `ls` и используют его формат без наших иконок. Это небольшой обозреватель дерева, а не полная замена всех возможностей `ls`.

Цвета и состав строки находятся в `shell/prompt.sh`. Git разбирается в `shell/git-status.sh`. После правки файлов проекта снова выполните `bash install.sh` и откройте новую вкладку.

## Что меняет установщик

- Копирует модули в `${XDG_CONFIG_HOME:-$HOME/.config}/terminal-config`.
- Подключает их в конце `~/.bashrc` и обеспечивает загрузку из `~/.bash_profile`.
- Комментирует отдельные команды `source …/oh-my-bash.sh` и `. …/oh-my-bash.sh` в этих двух файлах. Папка старого oh-my-bash остаётся для восстановления.
- Сохраняет прочие команды, переменные и пользовательские функции. Новый `ls` заменяет прежний alias с таким же именем.
- Перед изменением существующего файла создаёт рядом копию `.bak.ДАТА-ВРЕМЯ`. Повторная установка без изменений не создаёт лишних блоков и копий.

Чтобы отключить оформление, удалите из `~/.bashrc` блок между `# >>> terminal-config bashrc >>>` и `# <<< terminal-config bashrc <<<`, затем откройте новую вкладку. Для возврата прежнего оформления восстановите `.bashrc` и `.bash_profile` из нужных резервных копий. Не восстанавливайте старые копии поверх более поздних нужных изменений.

## Проверки

```bash
bash tests/run.sh
```

Проверяются Git-состояния во временных репозиториях, установка в отдельный временный HOME, повторная установка, пути с пробелами, сокращение строки и защита от выполнения кода из имён каталогов и веток. Тесты не меняют настоящие настройки и не устанавливают пакеты.
